在部落格中累積的不僅是文章。解決問題的過程、學到新事物的瞬間，以及看待某個主題的觀點，都會一併留存下來。隨著時間流逝，這些紀錄便成為能展現我曾思考過什麼、又如何改變的寶貴資產。

那麼，這份資產該存放在何處呢？即使撰寫文章的平台變更或消失，我是否也應該能夠持續保存並經營這些內容呢？

**Gitblog 是一項能將公開文章與部落格程式碼儲存於我的 GitHub 儲存庫中，並可透過網頁或 AI 代理程式撰寫文章並發佈至我部落格的服務。** 在直接擁有並管理文章的基礎上，我們更增添了便捷的寫作功能以及與讀者互動的功能。

創建 Gitblog 的初衷源於以下五點考量：

## 1. 我写的文章应该由我自己拥有并管理

寫作時間越長，越重要的是對「能隨時翻閱這些文章」這份信念的堅持。我們認為，作者應該能夠親自保存、修改自己的紀錄，並在必要時將其移至其他地方。

Gitblog 的公開文章會以 Markdown 檔案的形式儲存於您的 GitHub 儲存庫中。您亦可一併管理包含圖片在內的部落格檔案與程式碼。若將儲存庫下載至個人電腦，即可在本地端閱讀、修改及備份文章，並能透過 Git 的變更歷史記錄查閱過往內容。

即使 Gitblog 服務終止，我帳戶中的儲存庫、保存在本地的文章以及部落格程式碼仍會保留。只要維持主機和網域，就能繼續提供已部署的靜態部落格；如有需要，亦可將檔案移轉至其他主機。不過，Gitblog 提供的瀏覽、訂閱等整合功能，則取決於服務的運作狀況。

這正是我們選擇以 GitHub 為基礎的原因。許多人已經在使用 GitHub，它透過公開儲存庫和 GitHub Pages 提供了建立部落格的基礎。即使是 GitHub Free 方案，也能使用公開儲存庫的 Pages 託管服務。服務範圍與使用限制均遵循 [GitHub 的政策](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)。

無論在何處撰寫文章，都能將公開文章的原始檔掌握在自己手中。這正是 Gitblog 的第一項原則。

## 2. 必須是能與 AI 協作的部落格

與 AI 共同撰寫文章已逐漸成為常態。從在備忘錄中撰寫草稿、整理複雜內容、潤飾句子，到翻譯成其他語言。正如程式設計代理程式能讀取並修改專案檔案一樣，我認為協助寫作的代理程式也應能直接處理部落格的檔案。

Gitblog 的部落格儲存庫中，包含了供 AI 代理程式參考的撰寫、翻譯與驗證指引及指令。只要將我的部落格儲存庫指定為工作對象給能讀取、修改本地檔案並執行指令的代理程式，便能在該環境中撰寫草稿並準備發佈。若具備必要的認證與權限，甚至能直接進行發佈。

例如，可以發出以下請求：

> 請讀取此部落格儲存庫中的 AGENTS.md 並遵循撰寫指引。請根據我留下的備註撰寫文章，並儲存為草稿以便我審閱。

審閱完成後，可接著請求進行翻譯、驗證及發佈。可執行的作業將視所使用代理程式的檔案存取範圍與指令執行權限而異。具體流程已整理於 [部落格撰寫・翻譯指南](https://github.com/gitblogapp/gitblog-blog/blob/main/docs/gitblog/authoring.md) 中。

Gitblog 不會強制您將文章交由特定的 AI 模型處理。您可以直接在網頁上撰寫、使用熟悉的編輯器，或是與 AI 協作。我們的目標是讓作者能選擇符合自身工作方式的工具。

## 3. 優質的文章應能跨越語言與工具的藩籬被發現

文章发布後，必須有人發現並閱讀它。有些人會透過搜尋引擎尋找答案，也有人會向 AI 服務提問以獲取相關資料。此外，還會有以不同語言閱讀的讀者。

Gitblog 提供多语言发布、搜索及 AI 存取的架构，以便触及这类的读者。

首先，您可以將用自己習慣的語言撰寫的原文，翻譯成所選語言後發布。系統支援透過連接 DeepL API 進行自動翻譯，或是審閱由人工或大型語言模型（LLM）產生的譯文後上傳。使用 DeepL 自動翻譯需另行取得 API 金鑰。若您自行管理翻譯，當原文內容變更時，系統會提供確認翻譯是否與最新內容相符的流程。

此外，為使搜尋引擎與 AI 工具能辨識文章內容與來源，範本已具備以下基礎架構：

- **供搜尋使用的頁面資訊：** 提供標題、說明、原文網址、網站地圖以及各語言頁面的連結。
- **說明文章脈絡的結構：** 提供作者與發佈日期等結構化資料，並可依需求新增核心答案、來源、問題與回答。
- **直接存取文字的途徑：** 根據設定，提供公開文章的 Markdown 版本以及文章清單 `llms.txt`。

此設計考量了在搜尋、回答及生成式 AI 環境中（通常稱為 SEO、AEO、GEO）的被發現可能性。其目的是以易於閱讀的方式呈現文章正文與上下文。搜尋結果的排名或 AI 回答中的引用由各服務決定，並非僅靠翻譯或技術設定即可保證。 [搜尋與 AI 存取指南](https://github.com/gitblogapp/gitblog-blog/blob/main/docs/gitblog/ai-discovery.md)。

您亦可在 Gitblog 內發現文章。加入資訊流的部落格文章經彙整後，將反映於「最新文章」、「熱門文章」及「趨勢」等探索頁面中。讀者可尋找感興趣的文章，並前往作者的部落格閱讀。

我們所期盼的，是擴大自己留下的紀錄能觸及那些需要該內容之人的可能性。

## 4. 對文章的共鳴將轉化為 GitHub 上的連結

讀到好文章時，自然會對作者的下一篇文章產生好奇。人們會想進一步了解：這位作者正在進行什麼樣的專案？又記錄了哪些想法？

在 Gitblog 上，這份關注將延伸為 GitHub 上的連結。**訂閱部落格會與該儲存庫的 GitHub 星標（Star）連結，追蹤作者則會與 GitHub 帳戶的「追蹤」（Follow）功能連結。** 讀者可以彙整感興趣的部落格或作者的文章來閱讀，而作者也能透過自己的紀錄，在 GitHub 上與讀者建立連結。

這看似微不足道，但我們認為這種連結意義重大。因為在程式碼與專案所展現的樣貌之外，文章與思考更為其增添了深度。闡述專案中做出的決策、解決問題的過程以及所學內容的文章，成為理解該人工作方式的另一條途徑。

「Star」或追蹤者數量並不能決定文章的價值。然而，當對我的文章產生共鳴的讀者，因此建立起期待下一則動態的關係時，這便足以成為我持續寫作的動力。

## 5. 即使在 AI 時代，寫作依然重要

當我們向 AI 提問時，其實是在寫作。我們會闡述期望的結果、整理條件，並在閱讀回答後再次提問。即使由 AI 代為撰寫提示詞和草稿，關於該提出什麼要求、該接受什麼結果的判斷過程，依然存在。

写作也是审视自身想法的过程。当为了说明而书写句子时，便会发现原本自以为了解的部分其实存在漏洞。我们会寻找依据、修正相互矛盾的主张，并将脉络串联起来，以便他人理解。

即使AI承接了更多工作，我們也不願忘記自己作為「決定何者重要、該採取何種行動」的人類角色。**即使在與AI共同撰寫的文章中，也不失自己的思考與判斷**，這正是我們所追求的寫作方式。

希望 Gitblog 能成為持續進行這類練習的空間。一個能將所學用自己的語言闡述、將經驗以具脈絡的方式記錄下來，並在時日過去後重讀以深化思考的空間。

但願累積優質文章的過程，能成為磨礪自身智慧的歷程。

## 開始使用 Gitblog

Gitblog 既可透過網頁版的 Studio 開始使用，也可在 GitHub 上直接建立部落格儲存庫，再於本機電腦上運作。首先，讓我們來了解如何使用 Studio。

### 1. 使用 GitHub 帳號註冊

前往 [Gitblog](https://gitblog.app/ko)，使用 GitHub 帳號註冊並登入。登入後，將進入用於建立與管理個人部落格的「Studio」。

### 2. 連結 GitHub App 並建立部落格

依照 Studio 的指引，在 GitHub 上安裝 Gitblog App，並授權其存取用於管理部落格的儲存庫。預覽並選擇範本後，設定部落格標題與儲存庫名稱。

![英文版 Gitblog Studio 中預覽並選擇基於 Svelte、Astro、React 及 Vanilla HTML 的部落格範本畫面。](/uploads/introducing-gitblog/templates-en.jpg)

*英文版 Studio 的範本選擇畫面。截至 2026 年 11 月 3 日。*

部落格檔案將建立在我的 GitHub 儲存庫中。託管方面，可使用 GitHub Pages，或連結我的 Cloudflare 帳戶以使用 Cloudflare Pages。完成所選方式的部署設定後，即可準備發佈文章。

### 3. 使用 Markdown 撰寫並發佈文章

在 Studio 的文章撰寫畫面中，輸入標題、說明及 Markdown 正文。您也可以上傳代表文章的縮圖封面圖片以及正文圖片。

撰寫過程中可先儲存為草稿，審閱內容後再儲存為已發佈狀態。儲存後可查看建置與發佈進度，待發佈完成後，即可在我的部落格中閱讀該文章。若需翻譯，只需設定部落格的翻譯語言及使用方式，即可同步運作。

### 從 GitHub 和本地電腦開始

若想使用本地编辑器或 AI 助手进行创作，可从 GitHub 挑选合适的 Gitblog 官方模板，直接开始操作。

1. **使用範本建立自己的部落格儲存庫。** 在您想要的官方範本的 GitHub 頁面中，使用該範本在您的帳戶中建立新的公開儲存庫。這將建立一個獨立於原始範本之外、由您自行管理的部落格儲存庫。
2. **將您的儲存庫複製到本地電腦。** 透過所建立儲存庫的網址執行 `git clone`，並將下載的資料夾在編輯器或 AI 代理程式中開啟作為工作對象。依照範本的指引安裝必要的開發工具與依賴項，並完成部落格網址、語言、託管等初始設定。
3. 在本地端撰寫並檢視文章。 在 `content/posts/` 中撰寫 Markdown 文章並加入圖片。您可以直接編輯，或要求 AI 代理程式讀取 `AGENTS.md` 並遵循撰寫指引。審閱草稿後將其設為已發佈狀態，並執行範本提供的驗證程序。
4. **將變更內容上傳至 GitHub 並進行部署。** 將文章與圖片提交（commit）並推送（push）至目標分支後，設定好的 GitHub Actions 工作流程會建置部落格並部署至選定的託管服務。請確認 Actions 的執行結果，並檢查實際部落格頁面是否已反映變更。

首次使用時，必須依照所選範本的 [初始設定指南](https://github.com/gitblogapp/gitblog-blog/blob/main/docs/gitblog/setup.md) 來準備發佈環境。之後便可遵循 **在本地端撰寫 → 審閱與驗證 → 提交與推送 → 確認發佈** 的流程來持續撰寫文章。

即使是在 GitHub 上自行建立的部落格，只要允許 Gitblog App 存取該儲存庫，即可透過 Studio 的既有部落格連結功能進行管理。您可根據工作需求，選擇「網頁端撰寫」或「本地端撰寫」其中一種方式。

## 從能永久保存文章的地方開始吧

Gitblog 致力於打造一種能將文章儲存於個人帳戶、使用熟悉的工具撰寫，並能透過不同語言與途徑觸及讀者的部落格。其核心理念在於相信：透過寫作，能更深入地理解自己的想法。

無需從一開始就寫出完美的文章。試著記錄今天新發現的事實、長期思考的問題，或是親自解決的某個難題吧。為這些記錄增添背景脈絡並加以潤飾的過程，將引領您寫出下一篇文章。

**在您擁有並經營的部落格中，逐步累積您的想法吧。**
