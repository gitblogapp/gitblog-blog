如果每天早上都能查閱感興趣領域的新聞，把重要內容整理到自己的部落格裡，會怎麼樣？你可以將從研究到寫作、發布的工作交給自己的 AI 助理。

**Gitblog 提供寫作指南與指令，讓 AI 代理在你的部落格儲存庫中撰寫、驗證並發布文章。** 為能夠操作檔案與執行指令的代理連接 GitHub 存取權限後，對話中的請求就能一路推進到文章發布。

![以霓虹卡片格狀排列展示多款 AI 代理應用程式的圖片](/uploads/gitblog-agent-integration/ai-agent-apps.png)

本文以 Muse 為例，介紹連接儲存庫、GitHub 驗證、撰寫首篇文章及設定定期發布的流程。對於 Dots、Grokbot、Duet、Openclaw，只要環境支援儲存庫存取、指令執行與排程執行，也可以採用相同方式。連接方法與自動化範圍取決於各代理的功能和設定。

## 將部落格交給代理代表什麼

透過 Gitblog 發布的文章會以 Markdown 檔案保存在你自己的 GitHub 儲存庫中。代理撰寫與修改這些檔案，並依照儲存庫內的指南準備發布。

例如，一次請求可以串聯以下工作：

1. 研究感興趣主題的最新資料。
2. 核實來源，依部落格的讀者定位與文風寫作。
3. 按設定的方式準備翻譯，驗證文章與建置結果。
4. 將獲准發布的文章提交並 push 到 GitHub。
5. 檢查部署結果與實際文章網址，再回報結果。

結合代理的排程功能，就能讓它定期執行相同工作。**按時啟動代理是所用代理服務的職責；儲存、驗證與部署文章的基礎則由 Gitblog 儲存庫提供。**

## 1. 告訴 Muse 你的部落格儲存庫

先準備自己的 Gitblog 儲存庫。已有部落格可直接使用現有儲存庫；如果還沒有，請參考 [Gitblog 入門](/blog/2026-11-03-introducing-gitblog/)，透過 Studio 或喜歡的官方範本建立。

提供給 Muse 的應是**在你自己帳號下建立的部落格儲存庫網址**，而非範本的原始儲存庫。若儲存庫已在本機電腦上，也可將該資料夾指定為工作目錄。

可以試著提出以下請求，將 `OWNER/REPO` 換成自己的儲存庫位址。

```text
https://github.com/OWNER/REPO

이 저장소를 내 블로그로 사용할 수 있게 세팅해줘.
필요하면 작업 환경에 clone하고, 저장소의 AGENTS.md를 먼저 읽어줘.
npm run author:context로 현재 설정을 확인하고,
개인 작성 지침과 공식 설정·인증·글쓰기 안내를 따라줘.

이미 운영 중인 블로그라면 기존 주소, 언어, 번역 설정을 유지해줘.
처음 설정하는 블로그라면 필요한 선택 사항을 나에게 물어봐줘.
GitHub 인증이 필요하면 로그인 또는 토큰 방식으로 안내해줘.
설정이 끝나면 글 작성과 배포에 필요한 준비 상태를 알려줘.
```

![向 Muse 提供 agentic-blog 儲存庫網址和設定請求，並獲得 GitHub 連接與儲存庫選擇指引的對話畫面](/uploads/gitblog-agent-integration/muse-repository-setup.png)

*提供部落格儲存庫後，Muse 可以從連接 GitHub 與選擇可存取的儲存庫開始引導你。*

儲存庫中的 `AGENTS.md` 是告訴代理從何開始的入口。透過相關文件與指令，代理能了解文章位置、翻譯設定與驗證方法。這種方式以儲存庫為工作對象，不必為特定模型另外連接寫作 API。

## 2. 透過 GitHub 登入或權杖授予權限

在本機寫文章與上傳至 GitHub 並公開，是兩個不同階段。如果要將部署也交給代理，其工作環境需要備妥 Git 與 GitHub CLI 驗證。

若已有連接的帳號，就檢查並沿用現有驗證。若需要重新驗證，可依環境選擇瀏覽器登入或細粒度個人存取權杖（PAT）。

使用瀏覽器登入時，需要你親自完成代理指引的 GitHub 驗證流程。使用權杖時，應指定自己的部落格儲存庫，並依工作授予權限。初次設定與向已設定的部落格發布文章所需的權限不同，請依儲存庫的 [GitHub 驗證指南](https://github.com/gitblogapp/gitblog-blog/blob/main/docs/gitblog/github-auth.md)設定。

### 請 Muse 使用權杖連接

向 Muse 提出「改用 GitHub 核發的權杖，不使用登入方式」，即可取得如下建立權杖與設定權限的說明。範例連接的是 `elixirevo/agentic-blog`；實際操作時請選擇自己的帳號和儲存庫。

![Muse 以英語說明如何建立 GitHub 細粒度 PAT 並設定儲存庫權限的對話畫面](/uploads/gitblog-agent-integration/muse-token-guide.png)

*請求使用權杖連接後，可以取得核發步驟與任務所需權限的說明。*

### 在 GitHub 選擇目標儲存庫與權限

在權杖建立頁輸入容易辨識的名稱，並在 `Resource owner` 選擇部落格儲存庫的擁有者。將 `Repository access` 設為 `Only select repositories`，再選擇自己的部落格。截圖中選擇了 `No expiration`，但實際使用時應依工作期間設定到期日。

![在 GitHub 建立權杖時填寫名稱與擁有者，並僅選擇 agentic-blog 儲存庫的畫面](/uploads/gitblog-agent-integration/github-token-repository.png)

*將權杖可存取的儲存庫限制為自己的部落格。*

接著依工作內容設定權限。圖中是初次設定範例，包含 `Contents` 與 `Administration` 的寫入權限。若只是向已設定的部落格發布文章，不必照搬截圖中的所有權限；請先查閱前面連結的驗證指南，確認該操作需要的項目。

![GitHub 權杖權限畫面：Contents 與 Administration 可讀寫，Actions 與 Discussions 為唯讀](/uploads/gitblog-agent-integration/github-token-permissions.png)

*確認所需權限後，透過 `Generate token` 核發權杖。*

### 在 Muse 的專用畫面輸入權杖

透過代理指引的機密資訊輸入方式提供權杖，不要貼到聊天、文章內文或儲存庫檔案中。在 Muse 的 `Secure Login Information Storage` 畫面，確認連接目標為 `api.github.com`，在專用欄位輸入權杖後選擇 `Add`。

![Muse 的 Secure Login Information Storage 畫面，顯示 api.github.com 與權杖輸入欄位](/uploads/gitblog-agent-integration/muse-token-storage.png)

*這是提供 GitHub 權杖的專用畫面，截圖中的權杖欄位留空。*

驗證完成後，確認**代理實際工作的環境**能否存取儲存庫。

## 3. 用第一篇文章確認寫作流程

開始定期發布前，先用一篇文章確認結果是否符合預期。除了主題，同時說明讀者、篇幅與來源標準，更容易對齊文章方向。

```text
이 블로그에 올릴 첫 글의 초안을 작성해줘.

주제: 최근 24시간의 암호화폐 시장 주요 뉴스
독자: 비트코인과 이더리움의 흐름을 이해하고 싶은 일반 독자
언어: 한국어
분량: 5분 정도에 읽을 수 있는 길이

주요 뉴스의 원문 링크와 발표 시각을 확인해줘.
가격과 변동률에는 데이터 출처와 기준 시각을 적어줘.
확인된 사실과 해석을 구분하고, 인과관계가 불분명하면 단정하지 마.
먼저 미발행 초안으로 저장하고 내가 검토할 수 있게 보여줘.
```

閱讀草稿，檢查是否包含你重視的新聞，以及說明是否過於複雜或冗長。可以提出「先說重點」「比起技術變化，多談實際應用」等修改方向。

你可以請代理將長期適用的讀者定位、文風與來源標準整理到 `.gitblog/user-instructions.md`。這樣不必每次重複說明，也能為後續文章留下參考標準。

確認內容後，請求發布。

```text
검토한 초안을 발행해줘.
블로그의 번역 설정에 맞춰 발행을 준비하고 필요한 검증을 실행해줘.
검증을 통과하면 이번 글에 필요한 변경만 커밋하고 배포해줘.
배포가 끝나면 실제 글 주소를 확인해서 알려줘.
Gitblog 피드 반영 여부도 배포 결과와 구분해서 알려줘.
```

這個過程可以確認從寫作、更新 GitHub 到實際網站部署的完整流程。收到 push 完成的訊息不代表部署已完成，最後還要確認文章網址能正常開啟。

## 4. 請代理每天早上 8 點撰寫報告

如果首篇文章的結果符合預期，就依相同標準請求重複工作。排程時要說明時區、執行頻率、研究範圍與是否允許公開。

以下是每天早上撰寫並發布加密貨幣市場報告的請求範例。早上 8 點是開始工作的時間，研究與部署結束後才會收到結果。

```text
이 블로그 저장소로 다음 작업을 예약해줘.

매일 오전 8시, 한국 시간 Asia/Seoul 기준으로 작업을 시작해줘.
최근 24시간의 암호화폐 시장 주요 뉴스를 리서치하고,
비트코인과 이더리움의 가격·거래량 변화와 함께 읽을 수 있는
한국어 리포트를 작성해줘.

글에는 다음 내용을 담아줘.
- 오늘 알아야 할 핵심 내용
- 주요 뉴스 3~5개와 원문 출처
- 비트코인·이더리움의 변화, 데이터 출처와 기준 시각
- 뉴스와 시장 움직임의 관련성에 대한 해석
- 다음에 확인할 일정이나 지표

발표된 사실과 해석을 구분하고, 확인되지 않은 수치나 원인을 만들지 마.
중요한 자료를 확인하지 못했다면 공개하지 말고 이유를 알려줘.

저장소의 개인 작성 지침과 공식 발행 절차를 따라줘.
이 조건을 충족하고 검증을 통과한 새 리포트는 매번 별도 승인 없이
발행해도 돼. 기존 글을 덮어쓰지 말고, 같은 날짜의 리포트가 이미
있으면 중복 발행하지 마.

배포 완료 후 실제 글 주소와 핵심 요약을 이 대화에 알려줘.
실패했다면 어느 단계에서 멈췄는지 알려줘.
예약이 등록되면 실행 주기, 시간대, 다음 실행 시각을 확인해줘.
```

若希望每次先審閱，可將發布要求改成「儲存為未發布草稿，在我確認後再公開」。依照自己的經營方式，決定交給代理的工作範圍。

提出請求後，要確認排程確實已建立。執行時，代理仍需能存取儲存庫、研究工具與 GitHub 驗證。若在本機執行，相關環境必須在排定時間保持運作。

## 5. 查看為你撰寫的文章

定期工作帶來的既是當天的回答，也是在部落格裡持續保存的紀錄。文章累積在儲存庫中，之後可以修改、比較，或作為下一篇文章的資料。

除了市場報告，同樣的流程也適用於其他紀錄。

- 每週整理關注的開放原始碼專案的版本發布與變更。
- 將閱讀資料與筆記彙整成每週學習紀錄。
- 研究某個技術領域的新發表，並撰寫解說文章。

交給代理的工作越多，說明自己重視什麼就越重要。閱讀結果並調整方向，便能逐步形成適合自己的寫作方式。

## 從 Muse 開始，使用自己選擇的代理

Gitblog 的代理整合以部落格儲存庫及其中的指南為基礎。不論使用 Muse、Dots、Grokbot、Duet 或 Openclaw，只要工具支援所需的檔案存取與指令執行，就能從提供儲存庫開始。若要定期發布，也要確認排程執行功能。

先請代理寫一篇草稿。確立文章標準後，再接上驗證與發布，並為想長期記錄的主題加入定期執行。

**你的 AI 助理為你寫作，而紀錄保留在屬於你自己的部落格裡。**

## 問題與解答

### 需要在 Gitblog 安裝 Muse 專用整合嗎？

本文的方法讓代理直接操作部落格儲存庫。它需要檔案存取權限、指令執行環境，以及部署所需的 GitHub 驗證。

### 每次公開文章都必須先確認嗎？

可以只讓代理寫草稿，也可以設定條件後允許自動發布。能否真正無人值守執行，取決於代理的核准政策與執行環境。

### 可以修改文章或更換代理嗎？

文章以 Markdown 檔案保存在儲存庫裡，可以自行修改，也可以讓其他代理連接同一個儲存庫。排程與驗證需要在新環境重新設定。
