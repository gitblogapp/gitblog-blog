毎朝、関心のある分野のニュースを調べて読み、大切な内容を自分のブログに残せたらどうでしょう。調査から執筆、公開までの作業を、自分のAIアシスタントに任せるのです。

**Gitblogは、AIエージェントがブログのリポジトリで記事を執筆し、検証してから公開できるように、執筆ガイドとコマンドを提供しています。** ファイルの操作とコマンドの実行ができるエージェントにGitHubへのアクセス権を与えると、会話での依頼をブログの公開までつなげられます。

![さまざまなAIエージェントアプリをネオンのカード状に並べた画像](/uploads/gitblog-agent-integration/ai-agent-apps.png)

この記事ではMuseを例に、リポジトリの接続、GitHub認証、最初の記事の執筆、定期公開の設定を紹介します。Dots、Grokbot、Duet、Openclawでも、リポジトリへのアクセス、コマンド実行、予約実行に対応する環境なら同じ方法を使えます。接続方法や自動化できる範囲は、各エージェントの機能と設定によって異なります。

## エージェントにブログを任せるということ

Gitblogで公開した記事は、自分のGitHubリポジトリにMarkdownファイルとして残ります。エージェントはこのファイルを作成・編集し、リポジトリ内のガイドに従って公開を準備します。

たとえば、1回の依頼を次の作業につなげられます。

1. 関心のあるテーマについて最新の資料を調べる。
2. 出典を確認し、ブログの読者と文体に合わせて記事を書く。
3. 設定された方法で翻訳を準備し、記事とビルドを検証する。
4. 公開を許可された記事をコミットし、GitHubにpushする。
5. デプロイ結果と実際の記事URLを確認して報告する。

エージェントの予約実行機能を組み合わせれば、同じ作業を定期的に任せられます。**予定時刻にエージェントを実行するのは利用するエージェントサービスの役割です。記事の保存、検証、デプロイの基盤はGitblogのリポジトリが提供します。**

## 1. Museにブログのリポジトリを伝える

まず、自分のGitblogリポジトリを用意します。運営中のブログがあれば、そのリポジトリをそのまま使えます。まだない場合は、[Gitblogを始める](/blog/2026-11-03-introducing-gitblog/)を参考に、Studioまたは好きな公式テンプレートから作成します。

Museにはテンプレートの原本ではなく、**自分のアカウントに作成したブログのリポジトリURL**を渡します。すでにローカルPCにある場合は、そのフォルダを作業対象に指定することもできます。

次のように依頼してみましょう。`OWNER/REPO`は自分のリポジトリのアドレスに置き換えます。

```text
https://github.com/OWNER/REPO

이 저장소를 내 블로그로 사용할 수 있게 세팅해줘.
필요하면 작업 환경에 clone하고, 저장소의 AGENTS.md를 먼저 읽어줘.
npm run author:context로 현재 설정을 확인하고,
개인 작성 지침과 공식 설정·인증·글쓰기 안내를 따라줘.

이미 운영 중인 블로그라면 기존 주소, 언어, 번역 설정을 유지해줘.
처음 설정하는 블로그라면 필요한 선택 사항을 나에게 물어봐줘.
GitHub 인증이 필요하면 로그인 또는 토큰 방식으로 안내해줘.
설정이 끝나면 글 작성과 배포에 필요한 준비 상태를 알려줘.
```

![Museにagentic-blogのURLと設定依頼を渡し、GitHub接続とリポジトリ選択の案内を受ける会話画面](/uploads/gitblog-agent-integration/muse-repository-setup.png)

*ブログのリポジトリを渡すと、MuseからGitHubへの接続とアクセス対象の選択について案内を受けられます。*

リポジトリの`AGENTS.md`は、エージェントがどこから作業を始めるかを示す入口です。関連ドキュメントとコマンドを通じて、記事の場所、翻訳設定、検証方法を確認できます。特定のモデル向けに別の執筆APIを接続する必要はなく、リポジトリ自体を作業対象にします。

## 2. GitHubログインまたはトークンで権限を与える

記事をローカルで書くことと、GitHubにアップロードして公開することは別の段階です。デプロイまで任せるには、エージェントの作業環境でGitとGitHub CLIの認証を準備しておく必要があります。

接続済みのアカウントがある場合は、その認証を確認して使います。新しく認証する場合は、環境に合わせてブラウザログインかFine-grained personal access token（PAT）を選べます。

ブラウザログインでは、エージェントが案内するGitHubの認証手続きを自分で完了します。トークンを使う場合は、自分のブログリポジトリを対象に指定し、作業に必要な権限を与えます。初期設定と設定済みブログへの投稿では必要な権限が異なるため、リポジトリの[GitHub認証ガイド](https://github.com/gitblogapp/gitblog-blog/blob/main/docs/gitblog/github-auth.md)に従って設定します。

### Museにトークンでの接続を依頼する

Museに「ログインの代わりにGitHubで発行したトークンを使うように設定して」と頼むと、次のような発行手順と権限設定の案内を受けられます。ここでは`elixirevo/agentic-blog`を接続しています。実際には自分のアカウントとブログリポジトリを選んでください。

![GitHub Fine-grained PATの作成とリポジトリの権限設定を案内するMuseの英語画面](/uploads/gitblog-agent-integration/muse-token-guide.png)

*トークンでの接続を依頼すると、発行手順と作業に必要な権限を確認できます。*

### GitHubで対象リポジトリと権限を選ぶ

トークン作成画面で分かりやすい名前を入力し、`Resource owner`でブログリポジトリの所有者を選びます。`Repository access`を`Only select repositories`にして、自分のブログを選択します。画像では`No expiration`ですが、実際には作業期間に合った有効期限を設定します。

![トークン名と所有者を指定し、agentic-blogだけをアクセス対象にしたGitHubのトークン作成画面](/uploads/gitblog-agent-integration/github-token-repository.png)

*トークンがアクセスできるリポジトリを自分のブログに限定します。*

次に、行う作業に合わせて権限を設定します。画像は初期設定の例で、`Contents`と`Administration`の書き込み権限などを含みます。設定済みブログへの投稿だけなら、画面の権限をすべて追加せず、先ほどの認証ガイドで必要な項目を確認します。

![ContentsとAdministrationを読み書き可能、ActionsとDiscussionsを読み取り専用にしたGitHubの権限画面](/uploads/gitblog-agent-integration/github-token-permissions.png)

*必要な権限を確認したら、`Generate token`でトークンを発行します。*

### Museの専用入力画面にトークンを渡す

トークンはエージェントが案内する秘密情報の入力方法で渡します。チャット、記事本文、リポジトリのファイルには貼り付けません。Museの`Secure Login Information Storage`画面で接続先が`api.github.com`であることを確認し、専用欄にトークンを入力して`Add`を選択します。

![api.github.comとトークン入力欄が表示されたMuseのSecure Login Information Storage画面](/uploads/gitblog-agent-integration/muse-token-storage.png)

*GitHubトークンを渡すための専用画面です。スクリーンショットでは入力欄を空にしています。*

認証後は、**エージェントが実際に作業する環境から**リポジトリにアクセスできるか確認します。

## 3. 最初の記事で執筆の流れを確認する

定期公開を始める前に、記事を1本作って期待どおりの結果になるか確認します。テーマだけでなく、読者、分量、出典の基準も伝えると方向性が合いやすくなります。

```text
이 블로그에 올릴 첫 글의 초안을 작성해줘.

주제: 최근 24시간의 암호화폐 시장 주요 뉴스
독자: 비트코인과 이더리움의 흐름을 이해하고 싶은 일반 독자
언어: 한국어
분량: 5분 정도에 읽을 수 있는 길이

주요 뉴스의 원문 링크와 발표 시각을 확인해줘.
가격과 변동률에는 데이터 출처와 기준 시각을 적어줘.
확인된 사실과 해석을 구분하고, 인과관계가 불분명하면 단정하지 마.
먼저 미발행 초안으로 저장하고 내가 검토할 수 있게 보여줘.
```

下書きを読み、自分にとって重要なニュースが含まれているか、説明が難しすぎたり長すぎたりしないか確認します。「要点から伝えて」「技術の変化より実際の利用例を詳しく」など、修正の方向を伝えましょう。

継続して使う読者像、文体、出典の基準は、`.gitblog/user-instructions.md`に整理するよう依頼できます。同じ説明を繰り返す代わりに、次の記事でも参照する基準を残せます。

内容を確認したら、公開を依頼します。

```text
검토한 초안을 발행해줘.
블로그의 번역 설정에 맞춰 발행을 준비하고 필요한 검증을 실행해줘.
검증을 통과하면 이번 글에 필요한 변경만 커밋하고 배포해줘.
배포가 끝나면 실제 글 주소를 확인해서 알려줘.
Gitblog 피드 반영 여부도 배포 결과와 구분해서 알려줘.
```

これで執筆、GitHubへの反映、サイトのデプロイまでの流れを確認できます。push完了のメッセージだけではデプロイ完了とは限らないため、最終的に記事URLが開くことまで確認します。

## 4. 毎朝8時にレポート作成を任せる

最初の結果に満足できたら、同じ基準で繰り返し作業を依頼します。予約にはタイムゾーン、頻度、調査範囲、公開の可否も指定します。

以下は、暗号資産市場のレポートを毎朝作成して公開する依頼例です。午前8時は作業の開始時刻で、調査とデプロイが終わった後に結果を受け取ります。

```text
이 블로그 저장소로 다음 작업을 예약해줘.

매일 오전 8시, 한국 시간 Asia/Seoul 기준으로 작업을 시작해줘.
최근 24시간의 암호화폐 시장 주요 뉴스를 리서치하고,
비트코인과 이더리움의 가격·거래량 변화와 함께 읽을 수 있는
한국어 리포트를 작성해줘.

글에는 다음 내용을 담아줘.
- 오늘 알아야 할 핵심 내용
- 주요 뉴스 3~5개와 원문 출처
- 비트코인·이더리움의 변화, 데이터 출처와 기준 시각
- 뉴스와 시장 움직임의 관련성에 대한 해석
- 다음에 확인할 일정이나 지표

발표된 사실과 해석을 구분하고, 확인되지 않은 수치나 원인을 만들지 마.
중요한 자료를 확인하지 못했다면 공개하지 말고 이유를 알려줘.

저장소의 개인 작성 지침과 공식 발행 절차를 따라줘.
이 조건을 충족하고 검증을 통과한 새 리포트는 매번 별도 승인 없이
발행해도 돼. 기존 글을 덮어쓰지 말고, 같은 날짜의 리포트가 이미
있으면 중복 발행하지 마.

배포 완료 후 실제 글 주소와 핵심 요약을 이 대화에 알려줘.
실패했다면 어느 단계에서 멈췄는지 알려줘.
예약이 등록되면 실행 주기, 시간대, 다음 실행 시각을 확인해줘.
```

毎回確認したい場合は、公開の指示を「未公開の下書きで保存し、私が確認してから公開して」に変更します。運営方法に合わせて、任せる範囲を決められます。

依頼後は、実際に予約が登録されたか確認します。実行時にも、リポジトリ、調査ツール、GitHub認証が利用できる必要があります。ローカル実行の場合は、予定時刻にその環境が動作していなければなりません。

## 5. 自分のために書かれた記事を読む

定期作業から得られるのは、その日の回答と、ブログに残り続ける記録です。記事はリポジトリに蓄積され、後で編集したり、比較したり、次の記事の資料にしたりできます。

市場レポート以外にも、同じ流れをさまざまな記録に使えます。

- 関心のあるオープンソースプロジェクトのリリースと変更点を毎週まとめる。
- 読んだ資料やメモを集めて、週ごとの学習記録を作る。
- 特定の技術分野の新しい発表を調べ、解説記事を公開する。

任せるほど、自分が何を重視するかを伝えることが大切になります。結果を読み、方向を調整しながら、自分に合う執筆の進め方を作れます。

## Museから始めて、自分の使うエージェントへ

Gitblogのエージェント連携は、ブログリポジトリとその中のガイドが基盤です。MuseだけでなくDots、Grokbot、Duet、Openclawでも、必要なファイル操作とコマンド実行に対応していれば、リポジトリを渡すところから始められます。定期公開を行うなら、予約実行機能も確認します。

まずは下書きを1本任せてみてください。記事の基準が定まったら検証と公開をつなぎ、継続して記録したいテーマには定期実行を加えます。

**AIアシスタントが自分のために記事を書き、その記録は自分の所有するブログに残ります。**

## 質問と回答

### GitblogにMuse専用の連携機能を入れる必要がありますか？

この方法では、エージェントがブログリポジトリを直接操作します。必要なのはファイルへのアクセス、コマンド実行環境、デプロイ用のGitHub認証です。

### 公開のたびに確認が必要ですか？

下書きまで任せることも、条件を決めて自動公開を許可することもできます。実際に無人実行できるかは、エージェントの承認ポリシーと実行環境によります。

### 記事を編集したり、別のエージェントに移ったりできますか？

記事はリポジトリ内のMarkdownファイルなので、自分で編集したり、別のエージェントを同じリポジトリに接続したりできます。予約と認証は、新しい環境で設定し直す必要があります。
