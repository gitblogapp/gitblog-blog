如果每天早上都能查阅感兴趣领域的新闻，把重要内容整理到自己的博客里，会怎么样？你可以把从调研到写作、发布的工作交给自己的 AI 助手。

**Gitblog 提供写作指南和命令，让 AI 智能体在你的博客仓库中撰写、验证并发布文章。** 为能够操作仓库文件和执行命令的智能体连接 GitHub 访问权限后，对话中的请求就可以一直推进到文章发布。

![以霓虹卡片网格展示多款 AI 智能体应用的图片](/uploads/gitblog-agent-integration/ai-agent-apps.png)

本文以 Muse 为例，介绍连接仓库、GitHub 认证、撰写首篇文章和设置定期发布的流程。对于 Dots、Grokbot、Duet、Openclaw，只要其环境支持仓库访问、命令执行和定时运行，也可以采用相同方式。具体连接方式和自动化范围取决于各智能体的功能与设置。

## 把博客交给智能体意味着什么

通过 Gitblog 发布的文章会以 Markdown 文件的形式保存在你自己的 GitHub 仓库中。智能体撰写和修改这些文件，并按照仓库内的指南准备发布。

例如，一次请求可以串联以下工作：

1. 调研感兴趣主题的最新资料。
2. 核实来源，按照博客的读者定位和文风写作。
3. 按配置的方式准备翻译，验证文章和构建结果。
4. 将获准发布的文章提交并 push 到 GitHub。
5. 检查部署结果和实际文章地址，再反馈结果。

结合智能体的定时运行功能，就能让它定期执行同样的工作。**按时启动智能体是所用智能体服务的职责；保存、验证和部署文章的基础由 Gitblog 仓库提供。**

## 1. 告诉 Muse 你的博客仓库

先准备自己的 Gitblog 仓库。已有博客可以直接使用现有仓库；如果还没有，请参考 [Gitblog 入门](/blog/2026-11-03-introducing-gitblog/)，通过 Studio 或喜欢的官方模板创建仓库。

交给 Muse 的应是**在你自己账户下创建的博客仓库地址**，而不是模板原仓库。如果仓库已在本地电脑上，也可以将该文件夹指定为工作目录。

可以尝试下面的请求，将 `OWNER/REPO` 替换为自己的仓库地址。

```text
https://github.com/OWNER/REPO

이 저장소를 내 블로그로 사용할 수 있게 세팅해줘.
필요하면 작업 환경에 clone하고, 저장소의 AGENTS.md를 먼저 읽어줘.
npm run author:context로 현재 설정을 확인하고,
개인 작성 지침과 공식 설정·인증·글쓰기 안내를 따라줘.

이미 운영 중인 블로그라면 기존 주소, 언어, 번역 설정을 유지해줘.
처음 설정하는 블로그라면 필요한 선택 사항을 나에게 물어봐줘.
GitHub 인증이 필요하면 로그인 또는 토큰 방식으로 안내해줘.
설정이 끝나면 글 작성과 배포에 필요한 준비 상태를 알려줘.
```

![向 Muse 提供 agentic-blog 仓库地址及配置请求，并获得 GitHub 连接和仓库选择指引的对话界面](/uploads/gitblog-agent-integration/muse-repository-setup.png)

*提供博客仓库后，Muse 可以从连接 GitHub 和选择可访问仓库开始引导你。*

仓库中的 `AGENTS.md` 是告诉智能体从哪里开始的入口。通过关联文档和命令，智能体可以了解文章位置、翻译设置与验证方法。这种方式以仓库为工作对象，无需为某个模型另外接入写作 API。

## 2. 通过 GitHub 登录或令牌授予权限

在本地写文章与上传到 GitHub 并公开，是两个不同阶段。如果要把部署也交给智能体，其工作环境需要准备好 Git 和 GitHub CLI 认证。

如果已有连接的账户，就检查并使用现有认证。如果需要重新认证，可根据环境选择浏览器登录或细粒度个人访问令牌（PAT）。

浏览器登录需要你亲自完成智能体指引的 GitHub 认证流程。使用令牌时，应指定自己的博客仓库，并按工作内容授予权限。首次配置与向已配置博客发布文章所需的权限不同，请按照仓库的 [GitHub 认证指南](https://github.com/gitblogapp/gitblog-blog/blob/main/docs/gitblog/github-auth.md)设置。

### 请求 Muse 使用令牌连接

向 Muse 提出“改用 GitHub 签发的令牌，不使用登录方式”，即可获得如下令牌创建和权限设置说明。示例连接的是 `elixirevo/agentic-blog`；实际操作时请选择自己的账户和博客仓库。

![Muse 用英语说明如何创建 GitHub 细粒度 PAT 并设置仓库权限的对话界面](/uploads/gitblog-agent-integration/muse-token-guide.png)

*请求使用令牌连接后，可以获得签发步骤和任务所需权限的说明。*

### 在 GitHub 选择目标仓库与权限

在令牌创建页输入容易识别的名称，在 `Resource owner` 中选择博客仓库所有者。把 `Repository access` 设为 `Only select repositories`，然后选择自己的博客。截图中选择了 `No expiration`，但实际使用时应按工作期限设置到期日。

![在 GitHub 创建令牌时填写名称和所有者，并仅选择 agentic-blog 仓库的界面](/uploads/gitblog-agent-integration/github-token-repository.png)

*将令牌的仓库访问范围限定为自己的博客。*

接着按工作内容设置权限。图中是首次配置示例，包含 `Contents` 和 `Administration` 的写入权限。如果只是向已配置的博客发布文章，无需照搬截图中的所有权限，应先查看前面链接的认证指南，确认该操作所需的项目。

![GitHub 令牌权限界面：Contents 和 Administration 为读写，Actions 和 Discussions 为只读](/uploads/gitblog-agent-integration/github-token-permissions.png)

*检查所需权限后，通过 `Generate token` 签发令牌。*

### 在 Muse 的专用界面中输入令牌

通过智能体指引的秘密信息输入方式提供令牌，不要把它粘贴到聊天、文章正文或仓库文件中。在 Muse 的 `Secure Login Information Storage` 界面，确认连接目标是 `api.github.com`，在专用输入框填写令牌，再选择 `Add`。

![Muse 的 Secure Login Information Storage 界面，显示 api.github.com 和令牌输入框](/uploads/gitblog-agent-integration/muse-token-storage.png)

*这是提供 GitHub 令牌的专用界面，截图中的令牌输入框为空。*

认证完成后，确认**智能体实际工作的环境**能否访问仓库。

## 3. 用第一篇文章检查写作流程

开始定期发布之前，先用一篇文章确认结果是否符合预期。除了主题，同时说明读者、篇幅与来源标准，更容易统一文章方向。

```text
이 블로그에 올릴 첫 글의 초안을 작성해줘.

주제: 최근 24시간의 암호화폐 시장 주요 뉴스
독자: 비트코인과 이더리움의 흐름을 이해하고 싶은 일반 독자
언어: 한국어
분량: 5분 정도에 읽을 수 있는 길이

주요 뉴스의 원문 링크와 발표 시각을 확인해줘.
가격과 변동률에는 데이터 출처와 기준 시각을 적어줘.
확인된 사실과 해석을 구분하고, 인과관계가 불분명하면 단정하지 마.
먼저 미발행 초안으로 저장하고 내가 검토할 수 있게 보여줘.
```

阅读草稿，检查是否包含你重视的新闻，解释是否过于复杂或冗长。可以提出“先说重点”“相比技术变化，多讲实际应用”等修改方向。

可以让智能体把长期适用的读者定位、文风和来源标准整理到 `.gitblog/user-instructions.md`。这样无需每次重复说明，也能为下一篇文章留下参考标准。

确认内容后，请求发布。

```text
검토한 초안을 발행해줘.
블로그의 번역 설정에 맞춰 발행을 준비하고 필요한 검증을 실행해줘.
검증을 통과하면 이번 글에 필요한 변경만 커밋하고 배포해줘.
배포가 끝나면 실제 글 주소를 확인해서 알려줘.
Gitblog 피드 반영 여부도 배포 결과와 구분해서 알려줘.
```

通过这个过程，可以检查从写作、更新 GitHub 到实际网站部署的完整流程。收到 push 完成的消息并不代表部署已经完成，最终还要确认文章地址能正常打开。

## 4. 让智能体每天早上 8 点撰写报告

如果首篇文章的结果符合预期，就按相同标准请求重复任务。预约时需要说明时区、执行频率、调研范围和是否允许公开。

下面是每天早上撰写并发布加密货币市场报告的请求示例。早上 8 点是开始工作的时间，调研和部署结束后才会收到结果。

```text
이 블로그 저장소로 다음 작업을 예약해줘.

매일 오전 8시, 한국 시간 Asia/Seoul 기준으로 작업을 시작해줘.
최근 24시간의 암호화폐 시장 주요 뉴스를 리서치하고,
비트코인과 이더리움의 가격·거래량 변화와 함께 읽을 수 있는
한국어 리포트를 작성해줘.

글에는 다음 내용을 담아줘.
- 오늘 알아야 할 핵심 내용
- 주요 뉴스 3~5개와 원문 출처
- 비트코인·이더리움의 변화, 데이터 출처와 기준 시각
- 뉴스와 시장 움직임의 관련성에 대한 해석
- 다음에 확인할 일정이나 지표

발표된 사실과 해석을 구분하고, 확인되지 않은 수치나 원인을 만들지 마.
중요한 자료를 확인하지 못했다면 공개하지 말고 이유를 알려줘.

저장소의 개인 작성 지침과 공식 발행 절차를 따라줘.
이 조건을 충족하고 검증을 통과한 새 리포트는 매번 별도 승인 없이
발행해도 돼. 기존 글을 덮어쓰지 말고, 같은 날짜의 리포트가 이미
있으면 중복 발행하지 마.

배포 완료 후 실제 글 주소와 핵심 요약을 이 대화에 알려줘.
실패했다면 어느 단계에서 멈췄는지 알려줘.
예약이 등록되면 실행 주기, 시간대, 다음 실행 시각을 확인해줘.
```

如果希望每次先审核，可把发布要求改为“保存为未发布草稿，在我确认后再公开”。你可以根据自己的运营方式决定交给智能体的范围。

提出请求后，要确认定时任务确实已建立。执行时，智能体仍需能够访问仓库、调研工具和 GitHub 认证。如果在本地运行，相关环境必须在预约时间保持运行。

## 5. 查看为你撰写的文章

定期任务带来的既是当天的回答，也是在博客中持续留存的记录。文章积累在仓库里，以后可以修改、比较，或作为下一篇文章的资料。

除了市场报告，同样的流程也适用于其他记录。

- 每周整理关注的开源项目的版本发布和变更。
- 将阅读资料与笔记汇总成每周学习记录。
- 调研某一技术领域的新发布，并撰写解读文章。

交给智能体的工作越多，说明自己看重什么就越重要。阅读结果并调整方向，可以逐步形成适合自己的写作方式。

## 从 Muse 开始，使用自己选择的智能体

Gitblog 的智能体集成以博客仓库及其中的指南为基础。无论使用 Muse、Dots、Grokbot、Duet 还是 Openclaw，只要工具支持所需的文件访问和命令执行，就可以从提供仓库开始。若要定期发布，还需确认定时运行功能。

先让智能体写一篇草稿。确定文章标准后，再接上验证与发布，并为想长期记录的主题增加定期执行。

**你的 AI 助手为你写作，记录则保留在属于你自己的博客里。**

## 问题与解答

### 需要在 Gitblog 安装 Muse 专用集成吗？

本文的方法是让智能体直接操作博客仓库。它需要文件访问权限、命令执行环境，以及用于部署的 GitHub 认证。

### 每次公开文章都必须先确认吗？

可以只让智能体写草稿，也可以设置条件后允许自动发布。能否真正无人值守运行，取决于智能体的审批政策和执行环境。

### 可以修改文章或更换智能体吗？

文章以 Markdown 文件保存在仓库中，可以自行修改，也可以让其他智能体连接同一个仓库。定时任务和认证需要在新环境中重新设置。
