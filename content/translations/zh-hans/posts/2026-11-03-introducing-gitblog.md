博客中积累的不仅仅是文章。解决问题的心路历程、学到新知识的瞬间，以及看待某个主题的视角，都会一并留存下来。随着时间的推移，这些记录将成为展现我曾思考过什么、又发生了怎样的变化的宝贵财富。

那么，这些资产应该保存在哪里呢？即使写作平台发生变更或消失，我也应该能够继续保存和运营它们，不是吗？

**Gitblog 是一项将公开文章和博客代码存储在个人 GitHub 仓库中，并支持通过网页或 AI 代理撰写文章并发布到个人博客的服务。**在自主拥有和管理文章的基础上，我们还增加了便捷的写作功能以及与读者互动的功能。

创建 Gitblog 的初衷源于以下五点思考：

## 1. 我写的文章应该由我自己拥有和管理

写得越久，越重要的是相信自己能够随时翻阅这些文章。我们认为，作者应该能够亲自保存、修改自己的记录，并在必要时将其迁移到其他地方。

Gitblog的公开文章以Markdown文件的形式存储在我的GitHub仓库中。包括图片在内的博客文件和代码也可以一并管理。将仓库下载到本地电脑后，即可在本地阅读、修改和备份文章，还可以通过Git的变更历史查看之前的版本。

即使 Gitblog 服务停止运营，我账户中的仓库以及保存在本地电脑上的文章和博客代码仍会保留。只要维持托管服务和域名，就能继续提供已发布的静态博客；如有需要，还可以将文件迁移到其他托管平台。不过，Gitblog 提供的浏览、订阅等联动功能则依赖于服务运营。

这也是我们选择基于 GitHub 的原因。许多人已经在使用 GitHub，它通过公开仓库和 GitHub Pages 提供了开始博客的基础。即使在 GitHub Free 版本中，也可以使用公开仓库的 Pages 托管服务。服务范围和使用限制遵循 [GitHub 的政策](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)。

无论在何处撰写文章，都能将公开文章的原始文件掌握在自己手中。这是Gitblog的第一原则。

## 2. 必须是一个支持 AI 的博客

与 AI 共同写作正变得越来越自然。从在笔记中撰写草稿，到梳理复杂内容、润色句子，再到翻译成其他语言。正如编程代理可以读取并修改项目文件一样，我认为辅助写作的代理也应当能够直接处理博客文件。

Gitblog的博客仓库中包含了供AI代理参考的撰写、翻译和验证指南及命令。如果将我的博客仓库指定为工作对象给能够读取、修改本地文件并执行命令的代理，便可以在该环境中撰写草稿并准备发布。在具备必要认证和权限的情况下，甚至可以一直进行到部署。

例如，可以发出如下请求：

> 请读取本博客存储库中的 AGENTS.md 文件，并遵循其中的撰写指南。请根据我留下的备注撰写文章，并将其保存为草稿以便我进行审阅。

审阅完成后，可以继续请求翻译、验证和发布。根据所用代理的文件访问范围和命令执行权限，可执行的操作会有所不同。具体流程已在[博客撰写·翻译指南](https://github.com/gitblogapp/gitblog-blog/blob/main/docs/gitblog/authoring.md)中整理说明。

Gitblog不会强制要求将文章委托给特定的AI模型。您可以直接在网页上撰写，使用熟悉的编辑器，或者与AI协同工作。我们的目标是让作者能够选择适合自己工作方式的工具。

## 3. 优质的文章应当能够跨越语言和工具的限制被发现

文章发布后，需要有人发现并阅读它。有人通过搜索引擎寻找答案，也有人通过向AI服务提问来获取相关资料。还有读者使用与我不同的语言阅读文章。

Gitblog 提供了支持多语言发布、搜索及 AI 访问的架构，以便触达此类读者。

首先，您可以将用自己习惯的语言撰写的原文翻译成所选语言并发布。系统支持连接 DeepL API 进行自动翻译，或审核由人工或大型语言模型（LLM）生成的译文后发布。使用 DeepL 自动翻译需要单独的 API 密钥。如果您自行管理翻译，当原文发生变更时，系统会提供验证翻译是否与最新内容一致的流程。

此外，为了让搜索引擎和AI工具能够识别文章内容和来源，模板中已具备以下基础要素：

- **用于搜索的页面信息：**提供标题、描述、原文地址、网站地图以及各语言版本页面的链接。
- **说明文章背景的结构：**提供作者和发布日期等结构化数据，并可根据需要添加核心答案、来源以及问答内容。
- **直接访问文本的途径：**根据设置，提供公开文章的Markdown版本以及文章列表`llms.txt`。

该设计充分考虑了在通常被称为SEO、AEO、GEO的搜索、问答及生成式AI环境中的可发现性。其目的是以便于阅读的方式呈现文章正文及上下文。搜索结果的排名或AI回答中的引用由各服务自行决定，并非仅通过翻译或技术设置即可保证。 [搜索与AI访问指南](https://github.com/gitblogapp/gitblog-blog/blob/main/docs/gitblog/ai-discovery.md)。

您也可以在Gitblog内部发现文章。加入信息流的博客文章经过收录后，会显示在“最新文章”、“热门文章”、“趋势”等浏览页面中。读者可以查找感兴趣的文章，并跳转至作者的博客进行阅读。

我们希望的是，扩大您留下的记录触达那些需要这些内容的人的可能性。

## 4. 对文章的共鸣将转化为 GitHub 上的连接

读到一篇好文章后，人们自然会好奇作者的下一篇文章。于是，大家会去了解作者正在开发什么项目，以及他记录了哪些想法。

在 Gitblog 上，这种关注会延伸为 GitHub 上的互动关系。**订阅博客将与该仓库的 GitHub 星标关联，关注作者则与 GitHub 账户的关注操作关联。**读者可以收集自己感兴趣的博客或作者的文章，而作者也能通过自己的记录在 GitHub 上与读者建立联系。

这看似微不足道，但我们认为这种联系意义重大。因为在代码和项目所展现的形象之外，文章和思想为其增添了新的维度。那些阐述项目决策、问题解决过程以及所学内容的文章，成为了理解其工作的另一条途径。

“Star”或关注者数量并不能决定文章的价值。但那些对我的文章产生共鸣的读者，会因此期待我的下一篇作品——这种关系的建立，本身就是坚持写作的动力。

## 5. 即使在AI时代，写作依然重要

当我们向AI提问时，其实是在写作。我们需要阐述期望的结果、梳理条件，并在阅读回答后再次提问。即使AI代为撰写提示词和草稿，关于“请求什么”以及“接受何种结果”的判断过程依然存在。

写作也是审视自身思考的过程。在为阐明观点而书写句子的过程中，我们会发现那些自以为了解的部分其实存在漏洞。我们会寻找依据，修正相互矛盾的论点，并梳理上下文以便他人理解。

即使AI承担了更多工作，我们也不愿忘记自己作为人类在决定“什么重要”以及“该采取什么行动”中的角色。**即使在与AI共同创作的文章中，也不丢失自己的思考与判断**，这正是我们所追求的写作方式。

希望Gitblog能成为延续这种练习的空间。一个能用自己的语言阐释所学知识、将经验记录为有上下文的文字、并在时隔之后重读以深化思考的空间。

愿积累优质文章的过程，成为磨砺自身智慧的历程。

## 开始使用 Gitblog

Gitblog 既可以在 Web 端的 Studio 中开始，也可以在 GitHub 上直接创建博客仓库，然后在本地电脑上运行。首先，让我们来看看如何使用 Studio。

### 1. 使用 GitHub 账号注册

访问 [Gitblog](https://gitblog.app/ko)，使用 GitHub 账号注册并登录。登录后，进入用于创建和管理个人博客的 Studio 界面。

### 2. 连接 GitHub App 并创建博客

按照 Studio 的指引，在 GitHub 上安装 Gitblog App，并授权其访问用于管理博客的仓库。预览并选择模板后，设定博客标题和仓库名称。

![在英文版 Gitblog Studio 中预览并选择基于 Svelte、Astro、React 和 Vanilla HTML 的博客模板的界面。](/uploads/introducing-gitblog/templates-en.jpg)

*英文版 Studio 的模板选择界面。截至 2026 年 11 月 3 日。*

博客文件将创建在我的 GitHub 仓库中。托管方面，既可以使用 GitHub Pages，也可以连接我的 Cloudflare 账户来使用 Cloudflare Pages。完成所选方式的部署设置后，即可准备发布文章。

### 3. 使用 Markdown 撰写并发布文章

在 Studio 的文章编辑界面中，填写标题、描述和 Markdown 正文。还可以上传代表文章的缩略图封面图片以及正文中的图片。

撰写过程中可保存为草稿，审阅内容后保存为发布状态。保存后可查看构建和部署进度，部署完成后即可在我的博客上阅读文章。如需翻译，只需设置博客的翻译语言及使用方式，即可同步运营。

### 从 GitHub 和本地电脑开始

若希望使用本地编辑器或 AI 助手进行创作，可在 GitHub 上选择心仪的 Gitblog 官方模板直接开始。

1. **使用模板创建自己的博客仓库。** 在所需官方模板的 GitHub 页面上，使用该模板在您的账户中创建一个新的公开仓库。这样便会生成一个独立于原始模板、由您管理的博客仓库。
2. **将您的仓库克隆到本地电脑。** 访问所创建仓库的地址并运行 `git clone`，然后在编辑器或 AI 代理中打开下载的文件夹作为工作对象。按照模板的指引安装必要的开发工具和依赖项，并完成博客地址、语言、托管等初始设置。
3. **在本地撰写并预览文章。**在 `content/posts/` 中编写 Markdown 文章并添加图片。您可以直接编辑，也可以请求代理读取 `AGENTS.md` 并遵循撰写指南。审阅草稿后将其设为发布状态，并执行模板提供的验证流程。
4. 将文章和图片提交（commit）并推送到目标分支后，已配置的 GitHub Actions 工作流将构建博客并发布到所选的托管平台。请确认 Actions 的执行结果以及实际博客页面是否已更新。

首次使用时，需按照所选模板的[初始设置指南](https://github.com/gitblogapp/gitblog-blog/blob/main/docs/gitblog/setup.md)准备部署环境。此后，即可按照**本地撰写 → 审核与验证 → 提交并推送 → 确认部署**的流程继续撰写文章。

在 GitHub 上直接创建的博客，只要允许 Gitblog App 访问该仓库，即可通过 Studio 的现有博客连接功能进行管理。您可以根据工作需求，在“网页端”和“本地”两种使用方式中选择适合的方法。

## 从能留存自己文章的地方开始吧

Gitblog致力于打造一种能够将文章保存在个人账户中、使用熟悉的工具进行创作、并通过多种语言和渠道与读者相遇的博客。其核心理念是相信通过写作，能够更深入地理解自己的想法。

无需一开始就写出完美的文章。试着记录今天新了解的事实、长期思考的问题，或是亲手解决的一个难题吧。为这些记录增添背景并加以润色的过程，将自然地延续到下一篇文章中。

**在属于你并由你运营的博客中，逐步积累你的思考吧。**
