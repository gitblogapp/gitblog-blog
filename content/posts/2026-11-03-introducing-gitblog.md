블로그에 쌓이는 것은 글만이 아닙니다. 문제를 해결한 과정, 새로운 것을 배운 순간, 어떤 주제를 바라보는 관점이 함께 남습니다. 시간이 지나면 그 기록은 내가 무엇을 고민하고 어떻게 달라졌는지 보여 주는 자산이 됩니다.

그렇다면 이 자산은 어디에 남아야 할까요? 글을 쓰던 서비스가 바뀌거나 사라져도, 내가 계속 보관하고 운영할 수 있어야 하지 않을까요?

**Gitblog는 내 GitHub 저장소에 공개 글과 블로그 코드를 보관하고, 웹이나 AI 에이전트로 글을 작성해 내 블로그에 배포할 수 있는 서비스입니다.** 글을 직접 소유하고 관리하는 기반 위에, 편리한 글쓰기와 독자를 만날 수 있는 기능을 더했습니다.

Gitblog를 만든 이유는 다섯 가지 생각에서 출발합니다.

## 1. 내가 쓴 글은 내가 소유하고 관리할 수 있어야 합니다

글을 오래 쓸수록 중요한 것은 그 글을 계속 꺼내 볼 수 있다는 믿음입니다. 우리는 작성자가 자신의 기록을 직접 보관하고, 수정하고, 필요하다면 다른 곳으로 옮길 수 있어야 한다고 생각합니다.

Gitblog의 일반 공개 글은 내 GitHub 저장소에 Markdown 파일로 저장됩니다. 이미지를 비롯한 블로그 파일과 코드도 함께 관리할 수 있습니다. 저장소를 내 PC로 내려받으면 로컬에서 글을 읽고 수정하고 백업할 수 있고, Git의 변경 이력으로 이전 내용을 확인할 수도 있습니다.

**Gitblog 서비스가 없어지더라도 내 계정의 저장소와 로컬에 보관한 글, 블로그 코드는 남습니다.** 호스팅과 도메인을 유지하면 배포된 정적 블로그를 계속 제공할 수 있고, 필요하면 파일을 다른 호스팅으로 옮길 수 있습니다. 다만 Gitblog가 제공하는 탐색·구독 같은 연동 기능은 서비스 운영에 의존합니다.

우리가 GitHub를 기반으로 선택한 이유도 여기에 있습니다. 많은 사람이 이미 사용하고 있으며, 공개 저장소와 GitHub Pages를 통해 블로그를 시작할 수 있는 기반을 제공합니다. GitHub Free에서도 공개 저장소의 Pages 호스팅을 사용할 수 있습니다. 제공 범위와 이용 한도는 [GitHub의 정책](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)을 따릅니다.

글을 어디서 쓰든, 공개 글의 원본을 내 손에 둘 수 있도록 하는 것. 이것이 Gitblog의 첫 번째 원칙입니다.

## 2. AI도 사용할 수 있는 블로그여야 합니다

AI와 함께 글을 쓰는 일이 자연스러워지고 있습니다. 메모에서 초안을 만들고, 복잡한 내용을 정리하고, 문장을 다듬고, 다른 언어로 번역합니다. 코딩 에이전트가 프로젝트의 파일을 읽고 수정하듯, 글쓰기를 돕는 에이전트도 블로그의 파일을 직접 다룰 수 있어야 한다고 생각합니다.

Gitblog의 블로그 저장소에는 AI 에이전트가 참고할 작성·번역·검증 지침과 명령이 포함되어 있습니다. 로컬 파일을 읽고 수정하며 명령을 실행할 수 있는 에이전트에 내 블로그 저장소를 작업 대상으로 지정하면, 그 환경에서 초안을 작성하고 발행을 준비할 수 있습니다. 필요한 인증과 권한을 갖춘 경우에는 배포까지 이어 갈 수 있습니다.

예를 들어 다음과 같이 요청할 수 있습니다.

> 이 블로그 저장소의 AGENTS.md를 읽고 작성 지침을 따라줘. 내가 남긴 메모를 바탕으로 글을 작성하고, 검토할 수 있도록 초안으로 저장해줘.

검토를 마친 뒤에는 번역과 검증, 배포를 이어서 요청할 수 있습니다. 사용하는 에이전트의 파일 접근 범위와 명령 실행 권한에 따라 가능한 작업은 달라집니다. 구체적인 흐름은 [블로그 작성·번역 안내](https://github.com/gitblogapp/gitblog-blog/blob/main/docs/gitblog/authoring.md)에 정리되어 있습니다.

Gitblog는 특정 AI 모델에 글을 맡기도록 강제하지 않습니다. 웹에서 직접 쓰거나, 익숙한 편집기를 사용하거나, AI와 함께 작업할 수 있습니다. 작성자가 자신의 방식에 맞는 도구를 고를 수 있도록 하는 것이 목표입니다.

## 3. 좋은 글은 언어와 도구를 넘어 발견될 수 있어야 합니다

글을 발행한 뒤에는 누군가 그 글을 발견하고 읽어야 합니다. 검색엔진에서 답을 찾는 사람도 있고, AI 서비스에 질문하며 관련 자료를 만나는 사람도 있습니다. 내가 사용하는 언어와 다른 언어로 읽는 독자도 있습니다.

Gitblog는 이런 독자에게 다가갈 수 있도록 다국어 발행과 검색·AI 접근을 위한 구조를 제공합니다.

먼저, 내가 편한 언어로 쓴 원문을 선택한 언어로 번역해 게시할 수 있습니다. DeepL API를 연결해 자동 번역하거나, 사람 또는 LLM이 작성한 번역본을 검토해 등록하는 방식을 지원합니다. DeepL 자동 번역에는 별도의 API 키가 필요합니다. 직접 번역을 관리하는 경우에는 원문이 바뀌었을 때 번역도 최신 내용에 맞는지 확인하는 절차를 제공합니다.

또한 검색엔진과 AI 도구가 글의 내용과 출처를 파악할 수 있도록 템플릿에 다음과 같은 기반을 갖추었습니다.

- **검색을 위한 페이지 정보:** 제목과 설명, 원문 주소, 사이트맵, 언어별 페이지 연결을 제공합니다.
- **글의 맥락을 설명하는 구조:** 작성자와 발행일 등의 구조화 데이터를 제공하며, 필요에 따라 핵심 답변·출처·질문과 답변을 추가할 수 있습니다.
- **텍스트에 직접 접근하는 경로:** 설정에 따라 공개 글의 Markdown 버전과 글 목록인 `llms.txt`를 제공합니다.

흔히 SEO, AEO, GEO라고 부르는 검색·답변·생성형 AI 환경에서의 발견 가능성을 고려한 설계입니다. 목적은 글의 본문과 맥락을 읽기 쉽게 제공하는 데 있습니다. 검색 결과의 순위나 AI 답변에서의 인용은 각 서비스가 결정하며, 번역이나 기술적인 설정만으로 보장되지는 않습니다. [검색과 AI 접근 안내](https://github.com/gitblogapp/gitblog-blog/blob/main/docs/gitblog/ai-discovery.md).

Gitblog 안에서도 글을 발견할 수 있습니다. 피드에 참여한 블로그의 글은 수집을 거쳐 최신 글·인기 글·트렌딩 등의 탐색 화면에 반영됩니다. 독자는 관심 가는 글을 찾고 작성자의 블로그로 이동해 읽을 수 있습니다.

우리가 바라는 것은 내가 남긴 기록이 그 내용을 필요로 하는 사람에게 닿을 가능성을 넓히는 일입니다.

## 4. 글에 대한 공감이 GitHub의 연결로 이어집니다

좋은 글을 읽으면 작성자의 다음 글도 궁금해집니다. 어떤 프로젝트를 만드는 사람인지, 또 어떤 생각을 기록하고 있는지 찾아보게 됩니다.

Gitblog에서는 이런 관심이 GitHub의 관계로도 이어집니다. **블로그 구독은 해당 저장소의 GitHub Star와, 작성자 팔로우는 GitHub 계정의 Follow와 연결됩니다.** 독자는 관심 있는 블로그나 작성자의 글을 모아 볼 수 있고, 작성자는 자신의 기록을 통해 GitHub에서도 독자와 연결될 수 있습니다.

사소해 보일 수 있지만, 우리는 이 연결이 의미 있다고 생각합니다. 코드와 프로젝트를 통해 드러나는 모습에 글과 생각이 더해지기 때문입니다. 프로젝트에서 내린 결정, 문제를 해결한 과정, 배운 내용을 설명하는 글은 그 사람의 작업을 이해하는 또 하나의 통로가 됩니다.

Star나 팔로워 수가 글의 가치를 결정하지는 않습니다. 다만 내 글에 공감한 독자가 다음 기록을 기다리는 관계로 이어질 수 있다는 점은, 꾸준히 쓰는 이유가 될 수 있습니다.

## 5. AI 시대에도 글을 쓰는 일은 중요합니다

우리는 AI에 질문할 때 글을 씁니다. 원하는 결과를 설명하고, 조건을 정리하고, 답변을 읽으며 다시 질문합니다. AI가 프롬프트와 초안을 대신 작성하는 경우에도, 무엇을 요청할지와 어떤 결과를 받아들일지 판단하는 과정은 남습니다.

글을 쓰는 일은 자신의 생각을 살펴보는 과정이기도 합니다. 설명하려고 문장을 적다 보면 알고 있다고 생각했던 부분의 빈틈이 보입니다. 근거를 찾고, 서로 맞지 않는 주장을 고치고, 다른 사람이 이해할 수 있도록 맥락을 연결하게 됩니다.

AI가 더 많은 일을 맡게 되더라도, 우리는 무엇을 중요하게 여기고 어떤 행동을 할지 결정하는 사람의 역할을 잊지 않으려 합니다. **AI와 함께 쓴 글에서도 자신의 생각과 판단을 놓치지 않는 것**, 그것이 우리가 지향하는 글쓰기입니다.

Gitblog가 그런 연습을 이어 갈 수 있는 공간이었으면 합니다. 배운 것을 자기 언어로 설명하고, 경험을 맥락 있는 기록으로 남기고, 시간이 지난 뒤 다시 읽으며 생각을 발전시키는 공간 말입니다.

좋은 글을 쌓아 가는 일이 자신의 지성을 갈고닦는 과정이 되기를 바랍니다.

## Gitblog 시작하기

Gitblog는 웹의 Studio에서 시작할 수도 있고, GitHub에서 직접 블로그 저장소를 만든 뒤 로컬 PC에서 운영할 수도 있습니다. 먼저 Studio를 사용하는 방법부터 살펴보겠습니다.

### 1. GitHub 계정으로 가입하기

[Gitblog](https://gitblog.app/ko)에 접속해 GitHub 계정으로 가입·로그인합니다. 로그인한 뒤에는 내 블로그를 만들고 관리하는 공간인 Studio로 이동합니다.

### 2. GitHub App을 연결하고 블로그 만들기

Studio의 안내에 따라 GitHub에서 Gitblog App을 설치하고 블로그를 관리할 저장소 접근을 허용합니다. 템플릿을 미리 보고 선택한 다음 블로그 제목과 저장소 이름을 정합니다.

![영문 Gitblog Studio에서 Svelte, Astro, React, Vanilla HTML 기반 블로그 템플릿을 미리 보고 선택하는 화면.](/uploads/introducing-gitblog/templates-en.jpg)

*영문 Studio의 템플릿 선택 화면. 2026년 11월 3일 기준.*

블로그 파일은 내 GitHub 저장소에 생성됩니다. 호스팅은 GitHub Pages를 사용하거나 내 Cloudflare 계정을 연결해 Cloudflare Pages를 사용할 수 있습니다. 선택한 방식의 배포 설정을 완료하면 글을 올릴 준비가 됩니다.

### 3. Markdown으로 글을 쓰고 발행하기

Studio의 글 작성 화면에서 제목과 설명, Markdown 본문을 작성합니다. 글을 대표하는 썸네일용 커버 이미지와 본문 이미지도 업로드할 수 있습니다.

작성 중에는 초안으로 저장하고, 내용을 검토한 뒤 발행 상태로 저장합니다. 저장 후 빌드와 배포 진행 상황을 확인하고, 배포가 완료되면 내 블로그에서 글을 읽어 볼 수 있습니다. 번역이 필요하다면 블로그의 번역 언어와 사용 방식을 설정해 함께 운영하면 됩니다.

### GitHub와 로컬 PC에서 시작하기

로컬 편집기나 AI 에이전트로 작업하고 싶다면, GitHub에서 원하는 Gitblog 공식 템플릿을 골라 직접 시작할 수 있습니다.

1. **템플릿으로 내 블로그 저장소를 만듭니다.** 원하는 공식 템플릿의 GitHub 페이지에서 템플릿을 사용해 내 계정에 새 공개 저장소를 생성합니다. 원본 템플릿과 별개로 내가 관리할 블로그 저장소가 만들어집니다.
2. **내 저장소를 로컬 PC에 clone합니다.** 생성한 저장소의 주소로 `git clone`을 실행하고, 내려받은 폴더를 편집기나 AI 에이전트의 작업 대상으로 엽니다. 템플릿의 안내에 따라 필요한 개발 도구와 의존성을 설치하고, 블로그 주소·언어·호스팅 등 초기 설정을 완료합니다.
3. **로컬에서 글을 작성하고 확인합니다.** `content/posts/`에 Markdown 글을 작성하고 이미지를 추가합니다. 직접 편집하거나, 에이전트에 `AGENTS.md`를 읽고 작성 지침을 따르도록 요청할 수 있습니다. 초안을 검토한 뒤 발행 상태로 바꾸고, 템플릿이 제공하는 검증 절차를 실행합니다.
4. **변경 내용을 GitHub에 올려 배포합니다.** 글과 이미지를 커밋하고 배포 대상 브랜치에 push하면, 설정된 GitHub Actions 워크플로가 블로그를 빌드하고 선택한 호스팅에 배포합니다. Actions의 실행 결과와 실제 블로그 페이지에서 반영 여부를 확인합니다.

처음 한 번은 선택한 템플릿의 [초기 설정 안내](https://github.com/gitblogapp/gitblog-blog/blob/main/docs/gitblog/setup.md)에 따라 배포 환경을 준비해야 합니다. 이후에는 **로컬에서 작성 → 검토와 검증 → 커밋과 push → 배포 확인**이라는 흐름으로 글을 이어 갈 수 있습니다.

GitHub에서 직접 만든 블로그도 Gitblog App에 해당 저장소 접근을 허용하고 Studio의 기존 블로그 연결 기능을 통해 관리할 수 있습니다. 웹에서 쓰는 방식과 로컬에서 쓰는 방식 중 작업에 맞는 방법을 선택하면 됩니다.

## 내 글이 남는 곳에서 시작하세요

Gitblog는 글을 내 계정에 보관하고, 익숙한 도구로 작성하고, 다른 언어와 경로로 독자를 만날 수 있는 블로그를 지향합니다. 그 바탕에는 글을 통해 자신의 생각을 더 깊이 이해할 수 있다는 믿음이 있습니다.

처음부터 완벽한 글을 쓸 필요는 없습니다. 오늘 새롭게 알게 된 사실, 오래 고민한 질문, 직접 해결한 문제 하나를 기록해 보세요. 그 기록에 맥락을 더하고 다시 다듬는 과정이 다음 글로 이어집니다.

**내가 소유하고 운영하는 블로그에서, 나의 생각을 쌓아 가세요.**
